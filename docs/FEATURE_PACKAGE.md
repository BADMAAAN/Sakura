# Первый пакет SAKURA 0.3.0

Исторический отчёт именно 0.3.0. Последующая доработка общих Wi-Fi connect/scan и владения BLE описана в [0.3.1-back](BACK_FOLLOWUP.md); приведённые ниже ограничения и измерения относятся к указанному здесь бинарному файлу.

Пакет продолжает установленную SAKURA; сцена сакуры, шрифты, чёрная палитра, Home, батарея, sleep/wake, разделы и защита LittleFS от автоформатирования сохранены. Плата — LILYGO T-Embed CC1101 Plus, target `flux-delta`. Это авторское развитие FLUX/Bruce с прежними лицензиями, а не новая кодовая база с нуля.

## Back: причина и границы

GPIO верхней кнопки Back — 6, Select энкодера — 0; доказательства перепутанной распиновки не получено. Причины в коде: BLE info ожидал только Select; несколько BLE Spam циклов подавляли Back условием для трёхкнопочной платы; вложенные Whitelist/Media/Ninebot повторно потребляли cancel; блокирующий scan не опрашивал UI. Общий input терял события из-за медленного опроса/сброса и повторял удержанный уровень. Четыре поведенческих воспроизведения до исправления дали RED; тот же класс проверок после исправления PASS.

Проверены на host фактические обработчики общих меню, BLE list/config/info/scan/results/error, scan-completion race, Files и QR, debounce/press-release/быстрые Select→Back/удержание/wake/повторные входы. Settings → Diagnostics → Buttons действует только на своём экране; временный trace ограничен 16 событиями и выключен в обычной сборке. Подробнее: [hotfix](BACK_HOTFIX.md).

Пользователь на LilyGO подтвердил **Bluetooth → BLE Spam → режим/параметры без Start → поворот → короткий Back → повторный вход новым Select**. Это аппаратный PASS только данного сценария, не всех активных инструментов.

NimBLE 2.5.1 scan использует nonblocking start и проверенный stop, сохраняет экран до реальной остановки, при ошибке показывает её и позволяет повторить Back. Для принадлежащих инструменту Suite/Ninebot connect/discoverAttributes добавлен короткоживущий worker: UI быстро показывает Cancelling, отключает только этот client и ждёт завершения. Self-deleting clients отклоняются; worker удаляет только себя. После завершения worker и disconnect UI также ждёт подтверждения очереди NimBLE host: это исключает освобождение клиента посреди хвоста GAP callback. Back во время этого ожидания повторно проходит owned disconnect и новое host-подтверждение; занятость host показывается без опасного выхода по таймауту. Pending connect ждёт существующего конечного timeout NimBLE, потому что public cancelConnect отменяет глобальную GAP-процедуру. Подтверждение UI и фактическое завершение не смешиваются в одно измерение.

**Полный P0 остаётся открытым.** В активных Suite-инструментах есть синхронные refresh/read/write и циклы без Back во время ожидания; Ninebot buildModelOptions имеет writeValue и 2-секундную обратную связь; normal legacy cleanup может глобально deinit BLE. Эти пути не объявлены исправленными или аппаратно проверенными. Никакие радио-спам/атаки/передачи ради теста UI не запускались; используются инертные backend. Следующий этап — ограниченная квалификация и доработка конкретных оставшихся путей, а не обещание безопасной отмены всего наследуемого дерева.

Отдельная проверка фактического Wi-Fi wait дала 10 510 мс без потребления Back на fake backend. Один guard не решает задачу: вызывающий код различает лишь true/false, после чего предлагает Retry или следующую сеть; общий disconnect затрагивает чужое AP/сохранённые параметры. Замороженный пакет этот унаследованный путь не меняет; требуется согласованный Cancelled outcome и владение STA. Это конкретный известный дефект, не аппаратный PASS.

## Реально добавленные функции

- [Favorites / Recent](QUICK_ACCESS.md): устойчивые ID, 24 закрепления, порядок/удаление, безопасные экраны и ссылки SSH/QR; пять разных недавних в RAM с очисткой/отключением. Посещения не пишутся во flash.
- [SSH Profiles](SSH_PROFILES.md): 12 name/host/port/user, создание/редактирование/удаление/Favorites, карточка отдельно от Connect. Пароль в RAM, fingerprint и known_hosts до входа, таймауты и отмена. Реальный сервер не предоставлен; сетевое подключение не квалифицировано.
- [My QR](QR_CODES.md): название и текст/ссылка, просмотр/изменение/удаление/закрепление. Реальный генератор, 154 байта UTF-8, NUL/155 байт отклоняются. Программный декодер сравнивает точное содержимое ASCII/UTF-8/граничной строки. Прочтение телефоном отдельно не выполнено.
- BTC receive оставлен пустым; кошелёк, seed/private key и демонстрационный адрес не создавались. Поддерживается только существующий mainnet Base58Check P2PKH/P2SH.

## Реальная команда

Все делегирования выполнялись native collaboration tools, не имитировались последовательными действиями root. Вызваны восемь специалистов (не более трёх одновременно; повторные задачи используют тех же):

| Агент / роль | Реальная работа и доказательство |
|---|---|
| back_diagnosis / debugger | Цепочка GPIO→event→menu, четыре RED воспроизведения, анализ NimBLE API и оставшихся блокировок |
| back_tests / tester | 17 Back регрессий; независимые QR decode/CRUD/migration проверки и mutation checks |
| ble_hotfix / implementer | Исправление scan/cancel и последующая owned-client отмена; runnable backend со 100 циклами |
| hotfix_review / code_reviewer | Независимое ревью input/menus/SSH/QR/BLE, actual-module harness; найдены и исправлены потеря partial write, post-cancel continuation и ошибки сохранения |
| hotfix_build_audit / build-engineer | Проверка ESP image, rollback/partitions, аудит blobs/истории и просмотр 524 raster assets/363 animation frames |
| feature_inventory / explorer | Поиск существующих Favorites, SSH и QR до изменений, карта повторного использования |
| ssh_profiles / implementer | Профили и проверяемый SSH transport; host validators/storage/trust/deadlines |
| my_qr / implementer | Saved QR, immutable IDs/high-water migration, точный encoder и checked persistence |

Root владеет общим input, интеграцией навигации, сборкой, документацией и COM. Новых зависимостей для функций не добавлено. В `.codex/agent-team` хранится компактное состояние; native история содержит вызовы и отчёты команды.

## Установка и сохранение

0.2.0 и 0.2.1-back сохранены отдельно вместе с исходниками, hash, ELF и полным rollback. Приватные дампы находятся вне репозитория в `C:\Projects\FLUX-Backups\sakura-back-hotfix-20261016`; следующий пакет имеет отдельную свежую копию непосредственно перед записью. Установка допускает только application по `0x10000` после сравнения фактической partition table; prefix и data проверяются до reboot. Никакого erase_flash, форматирования, reset NVS, изменения разметки или записи SD.

Установка **PASS**: записан только app по `0x10000`; verify подтвердил приложение и побайтную сохранность prefix (загрузчик/разметка/NVS) и data (LittleFS/coredump) до reboot. Актуальный полный rollback 0.2.1, прочитанный до записи, имеет SHA-256 `64077f33509970c4733a2f6b6194b611c4f3bc99bdf5d782039aca1471f15348`; приложение в нём совпало с сохранённым hotfix. Во время исправления кандидата устройство оставалось в загрузчике, промежуточный образ не запускался.

После загрузки за 20 секунд наблюдения panic 0, Home renderer 62,29–62,34 FPS (три окна). Это cadence renderer, не частота физического LCD и не задержка кнопки. Heap free/total 145 203 / 267 827 B; free PSRAM 8 043 660 B. Перед обновлением использовавшаяся 0.2.1 дала 95 375 / 268 091 B и PSRAM 8 039 024 B; контекст отличается, поэтому улучшение/утечки по этим снимкам не заявляются.

Пользователь отдельно подтвердил Back во всех трёх меню установленной 0.3.0: Settings → Recent screens, Wi-Fi → SSH Profiles и Tools → QRCodes, без создания данных и Connect/Start. Это аппаратный PASS навигации этих меню; предыдущий Back PASS в BLE Spam относится к hotfix 0.2.1. Реальный SSH-сервер, чтение QR телефоном и stack-watermark не проверены.

Машинные результаты — `artifacts/sakura-features-validation.json`. Полный **локальный** source/dependency/history ZIP и соседний `.sha256` находятся в artifacts; приватные дампы исключены. Исторический локальный комплект отличается от фильтрованного состава публичной публикации.

## GitHub

[BADMAAAN/Sakura](https://github.com/BADMAAAN/Sakura) проверен пустым; существующий `origin` сохранён, добавлен отдельный `sakura`. Push/release не выполнялись. Аудит исходных blobs не нашёл доказанных живых токенов/ключей; изображения просмотрены, девять build logs и optional `media/pictures/nfc.gif` с UID исключаются из отдельного публичного состава. Существующая локальная история не переписывается. Чистый начальный снимок с provenance и его точный manifest предназначены для отдельного подтверждения первой публикации.

README, отслеживаемая Wiki, CHANGELOG, [roadmap](ROADMAP.md), управление и [известные проблемы](KNOWN_ISSUES.md) сохранены. Десять следующих направлений содержат зависимости, сложность и критерии, но не реализуются в этом пакете.

Дополнительная проверка памяти по реальному ELF обнаружила удержание двух SSH Store: минимальная вложенная цепочка 9 040 байт превышала loop stack 8 192. Менеджер теперь строит список через существующие id/name links, а Store создаёт только внутри Create; родитель не удерживает его во время открытия карточки. Runnable actual-manager тест отвергает прежний код; в финальном ELF frame менеджера снизился с 3 072 до 144 байт, известная вложенная цепочка — с 9 040 до 6 144 байт. Это не полный worst-case bound с NVS/всеми предками и не физический stack-watermark; такая квалификация остаётся отдельно. Лимит стека не увеличивался, старые возможности не вырезались.
