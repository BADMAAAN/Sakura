# FLUX DELTA — системный интерфейс

Исходная рабочая точка: `6ade36dd`, ветка разработки `codex/delta-system-ui`. Старый `C:\Projects\FLUX` используется только для чтения. Перед изменениями сохранены предыдущая установленная application, отчёт и полный Git bundle в `backups/system-ui-baseline-2026-10-15`.

## Объём и физические пути

Полная исходная карта: [31 строка общих семейств](FLUX-DELTA-SCREEN-MAP.md) и [120 файлов интерфейса](FLUX-DELTA-TOOL-SCREENS.md). Аудит включает 373 C/C++ файла, 90 файлов с прямым TFT-доступом, 2135 прямых обращений и 1747 общих UI-токенов. Это инвентарь кода, а не число физически испытанных экранов.

`MainMenu → loopOptions → исходный Option::operation` сохранён. REGULAR и SUBMENU теперь вызывают `deltaUiMenu`; Home использует прежний SINGLE-SLOT renderer. Это тот же путь, который собирается для LilyGO. Web preview не участвует в выполнении функций.

## Общий слой

`widgets.h`, `instruments.h`, `rf_graph.h` содержат общий C++11 рендер. `delta_ui.cpp` использует один существующий PSRAM framebuffer 108800 байт и собственный кэш текста меню. Передача отдельных областей учитывает stride 320. Графика в Arduino линкуется одной копией через `delta_artwork.cpp`; хостовые проверки сохраняют header-only вариант.

Анимация фокуса и открытия списка привязана к времени, заменяет предыдущую цель и не ставит переходы в очередь. `loopOptions` продолжает принимать ввод. Накопленные extreme INT32 пакеты энкодера сворачиваются в ограниченное число шагов; прокрутка текста сразу ограничивается границами. При выключенном экране/сне canvas и redraw останавливаются. Home сохраняет прежнюю декоративную анимацию. Терминал и живые графики не получают декоративных лепестков или искусственного сглаживания исходных данных.

## Сохранённая специализированная геометрия

Палитра стандартных TFT-токенов адаптируется в logger без изменения сохранённых цветов FluxConfig. Пиксельные изображения, QR, игровые поля, heatmap/sample pixels и явная графика JS сохраняются. Foreground JS и `runtime.main` обходят remapping цветов. Это сохраняет контракт графического API.

Пакетный BLE sniffer/hex, RFID hex/dump, декодированные RF поля (включая KeeLoq), плотные протокольные логи, микрофон/NRF/игровые графики и пользовательский script canvas сохраняют исходную геометрию данных. Общие меню и chrome получают DELTA там, где используются общие функции. Не утверждается, что каждый произвольный pixel/sprite/native вызов перекрашен или что все специализированные модули получили новый layout. Безопасное дальнейшее улучшение этих областей — отдельный output-only адаптер с тестом полного сохранения полей; изменения протоколов для этого не требуются.

Atlas покрывает ASCII 32–126. Неподдержанный Unicode показывается одним `?` на кодовую точку; оригинальные SSID, имена файлов и ввод не изменяются. Полный Unicode не заявлен.

## Проверки и независимое ревью

Хостовые проверки исполняют производственные функции: навигацию 13/16 категорий, вложенные callbacks и возврат, forced selection отдельно от выделенного индекса, disabled/empty, отмену, extreme encoder, перенос строк, keyboard masking/actions, scroll, нехватку framebuffer, mount-failure guards, battery/power и RF acquisition. Частотный тест сверяет порядок чтения/настройки/паузы/SPI sentinel и pixels общего рендера.

Независимое code review нашло и закрыло два P2: явные цвета `runtime.main` и недоступные нижние строки BLE profile. Независимое visual review закрыло перенос внутри слова, подписи гистограмм и контраст Dawn. После RGB565 контраст Dawn muted/focus — 4.82:1. PASS относится к проверенным хостовым кадрам; он не заменяет физическую приёмку.

[Сравнительный отчёт OLD UI → DELTA](FLUX-DELTA-VISUAL-COMPARISON.md) содержит 60 явно подписанных кадров и точное происхождение каждого. Значения PREVIEW являются тестовыми примерами, а не обнаруженными устройствами. Старые фотографии/RF-референс недоступны в текущих вложениях; точное сопоставление с ними не заявлено.

Использованы native специалисты `ui_map`, `ui_modules`, `ui_components`, `ui_common`, `ui_inputs`, `system_code_review`, `system_visual_review`, `system_build_audit`; root отвечает за архитектуру, интеграцию, сборку, аппаратное измерение и запись. Области записи разделялись; максимум три активных подагента. Подробные локальные доказательства — `.codex/ui-system`.

Сохранённый baseline-дефект BLE Suite: у множественного выбора отсутствует успешный выход с подтверждением (Next продолжает навигацию, Esc очищает выбор). Новое оформление это поведение не исправляет и не выдаёт его за проверенную успешную операцию. Это отдельный функциональный backlog; новые функции или радиодействия ради редизайна не добавлялись.

## Сборка и аппаратная приёмка

Итоговые размеры, установка, загрузка, FPS/память и ручные сценарии записываются в [отчёт проверки](FLUX-DELTA-SYSTEM-UI-VALIDATION.md). Старый baseline: application 4291296 байт, static RAM 132824 байта, измеренный Home 47.29 FPS. Цель 60 FPS не объявляется достигнутой по хостовому рендеру.

Перед записью повторно проверены приватный 16 MiB backup SHA-256, MAC устройства, flash ID/security и фактическая таблица разделов с MD5. Application размещается только в factory `0x10000..0x47ffff`; установщик не записывает bootloader/table/NVS/LittleFS/SD; явные изменения настроек сохраняются штатно. Автоформатирование при mount failure запрещено и покрыто регрессией. Активные радиотесты, SSH-команды и Deep Sleep автономно не запускаются.
