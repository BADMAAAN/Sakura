No network, radio, RFID write, script, SSH command, or device action was run during this inventory.

## Scope and reproducibility

All C/C++ source and headers below `src/` were searched, apart from the common display, keyboard, theme, Home, DELTA, branding and application entry sources owned by the separate common-renderer mapper. **373 files scanned; 120 UI-bearing files; 90 files with direct display access; 2,135 direct display invocations and 1,747 shared UI invocation tokens.** Counts strip comments. They include queries such as `width()`, formatting/state calls, optional build-excluded modules, header declarations and script drawing APIs: they are neither frame counts nor counts of independent screens. Module/menu-only first-pass raw `rg` counts are not comparable because they include comments and a narrower scope.

The full machine-readable audit is `.codex/ui-system/tool-screen-inventory.json`: every discovered direct invocation has a source line and method, files have UI function anchors, shared-function counts, control tokens, methods and literal colors. It includes the 253 source/header files with no matched display/shared-UI tokens. Function anchors use a bounded source regex, not a C++ parser; nested lambdas and multiline constructors can inherit a preceding anchor. Exact invocation lines remain authoritative.

Re-run source search:

```powershell
rg -n '\b(tft|sprite|spr|canvas|frame|_scrollBuffer)\s*(\.|->)' src --glob '*.{cpp,h,hpp,c}'
rg -n 'target\.(display|sprite)->|d->sprite->' src/modules/bjs_interpreter/display_js.cpp
rg -n '\b(loopOptions|drawOptions|listFiles|drawMainBorderWithTitle|drawMainBorder|displayError|displayInfo|displayTextLine|printTitle|printSubtitle|padprintln|keyboard|progressHandler|ScrollableTextArea)\s*\(' src --glob '*.{cpp,h,hpp,c}'
```

The excluded common files are `src/core/{display,mykeyboard,theme,main_menu,delta_ui,flux_branding}.{cpp,h}` plus `src/main.cpp`. Their common migration is a separate inventory responsibility. Module wrappers that only call shared menus are included here so deep paths remain visible.

## Completion gates

1. Common nested lists/dialogs/keyboard/viewer/progress must use the actual new DELTA implementation in firmware. Options continue invoking the same callbacks and preserving returned selection/cancel values.
2. Validate the custom UI islands above separately. A color replacement alone does not prove hierarchy, clipping, metadata readability, or Back behavior.
3. RF heatmap/waveform, terminal monospace, QR bitmap, games/mascot art and arbitrary script canvas are data/purpose-specific renderers. Their useful data or explicit API pixels remain intact; compatible chrome gets DELTA styling. Report any deliberate retained layout by file, rather than claiming an unverified universal migration.
4. Captures need multiple nested pages, real metadata paths exercised with injected fixtures, and representative specialist data. Hardware standard-menu paths require user confirmation after the verified application-only update. No active transmit/attack/network/script actions are required for UI verification.
5. LittleFS failure, unknown battery, display-off render suppression and wake behavior remain separate regression gates. No changes to mount policy, partition layout, protocol timing or storage contents are authorized by this UI audit.
