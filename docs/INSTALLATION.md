# Установка и сохранение данных

Эта инструкция относится к совместимому обновлению уже настроенной LILYGO T-Embed CC1101 Plus. Она не описывает первоначальную установку на пустую flash и не разрешает менять разметку.

## Перед записью

1. Закройте serial monitor и другие программы, занимающие COM-порт. Определите плату, порт, ESP32-S3, объём flash и security state чтением сведений устройства.
2. Сохраните проверенный резервный дамп вне репозитория; запишите размер и SHA-256. Сохраните важные файлы SD отдельно. Дамп может содержать личные настройки.
3. Прочитайте установленную partition table и сравните её с [custom_16Mb.csv](../custom_16Mb.csv). Не выводите установленную разметку только из файла исходников.
4. Соберите `flux-delta`, проверьте тесты, metadata и SHA-256 именно `.pio/build/flux-delta/firmware.bin`. Убедитесь, что приложение подходит существующему app-разделу.
5. Для текущей таблицы исходников factory начинается с `0x10000` и имеет размер `0x470000` (4 653 056 байт). Это ориентир для сверки, а не разрешение писать по адресу без чтения устройства.

## Запись

Используйте только проверенный **application-only** образ в существующем app-разделе. Не подставляйте merged distribution image, bootloader или partitions.bin. Команда записи зависит от установленной версии esptool и фактического порта; сначала сверяются её help и metadata.

Обычное совместимое обновление не требует `erase_flash`, factory reset, форматирования LittleFS/SD, стирания NVS или переноса разделов. Не запускайте эти операции для исправления UI. Если разметка, chip, размер или security state не совпали, прекратите запись и сохраните диагностику.

После записи выполните verify, перезагрузку и проверку boot log. Затем проверьте Home, вложенные меню, чёрный/белый/RGB, батарею, зарядку, сон/пробуждение и QR телефоном. Запишите hash, дату, результат и непроверенные случаи в отчёт конкретного образа. Успешная компиляция не заменяет эту проверку.

## Возврат и архив

При совместимой разметке возврат к прежнему проверенному application-only образу сохраняет разделы данных. Полный restore дампа — отдельная операция, способная заменить данные, и не входит в обычное обновление.

Локальный комплект должен содержать исходники с лицензиями, ресурсы, тесты, документы, application-only бинарный файл и его SHA-256. Отдельно храните приватный дамп; не добавляйте его, COM-логи с личными данными и `flux.conf` в публикуемый ZIP. Публикация в новый GitHub выполняется владельцем после выбора URL.
