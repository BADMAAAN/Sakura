# SAKURA 0.2.0 — проверка 16 октября 2026

Этот отчёт относится к ветке `codex/sakura-night`, исходная ревизия FLUX DELTA — `1c40059a`. Исходный checkout FLUX не изменялся. Сцена сохранена по явному выбору пользователя; BTC-адрес оставлен пустым.

## Диагностика и исправления

Приложенное изображение относится к BTC-депозиту, а не экрану LilyGO. Фотографий дисплея для визуальной диагностики нет. Следующие симптомы взяты из запроса и сопоставлены с кодом; они не выдаются за наблюдения по отсутствующим фото.

| Симптом | Проверенный путь и результат |
|---|---|
| Зеленоватые тени Home | В RGB565-палитре сцены есть почти чёрные оттенки с зелёным компонентом; для NIGHT самые тёмные оттенки приведены к нейтральному чёрному. Это корректировка теней, не доказанная причина всего аппаратного дефекта. |
| Другой фон вложенных меню | `workBackground` смешивал исходную сцену с подложкой. Общие экраны теперь используют ту же сцену, что Home. |
| Прямоугольники, счётчики и правая полоса | Основные mode/category painters рисовали несколько строк, панели и scrollbar. Теперь показывают один выбранный пункт; результаты и технические параметры сохраняют рабочие представления. |
| Батарейка меняет положение | Home и общие заголовки имели разные координаты. Теперь общий renderer; Confirm, Files и клавиатура тоже передают status. |
| Ложный низкий заряд | Чтения BQ27220 раньше не проверяли готовность gauging. Добавлены INITCOMP, CFGUPDATE, CALMD; неизвестное значение не заменяется фиктивным процентом. Реальная причина конкретного случая после зарядки требует проверки устройством. |
| Вспышка при wake | Яркость восстанавливалась до полного кадра. Retained SAKURA canvas передаётся до подсветки; прямые экраны сохраняют GRAM и не перекрываются старым меню. |
| Цвет при запуске/Deep Sleep | Старт удерживает backlight LOW до чёрно-розового экрана SAKURA; board, menu и serial sleep routes выключают экран до сна. Зарядный контроллер и разметка не изменены. |

Проверены canonical RGB565, blend, palette lookup, static cache, границы frame/partial push и byte swap. В bundled non-DMA transfer не найдено доказательств изменения исходного буфера. После установки пользователь подтвердил корректный вид Home, Wi-Fi и BLE без зелёной заливки/полосы. Это подтверждает исправление симптома на проверенных экранах; вклад каждого изменения в исходный аппаратный дефект отдельно не изолирован.

## Сборка и установка

Сборка `flux-delta`: **PASS**, 413.45 s. Версия продукта `SAKURA 0.2.0-sakura`; готовый ESP32-S3 image имеет корректные checksum и validation hash.

| Ресурс | Прежний образ | SAKURA | Изменение |
|---|---:|---:|---:|
| Application binary | 4 393 744 B | 4 394 320 B | +576 B |
| Linker RAM | 133 152 B | 133 160 B | +8 B |
| Запас application partition | 259 312 B | 258 736 B | −576 B |

SHA-256 application-only: `0c7f13cbce29f5a2adf13328ace7cd783e417467e526a7aa8d90e06a6b51b0f3`.

Поля ESP AppDescriptor унаследованы от предварительно собранного SDK (`arduino-lib-builder`, IDF version); они не являются пользовательской версией SAKURA. Пользовательские boot/About/info и version flags обновлены отдельно. В сборке остаются предупреждения унаследованных библиотек; подавления проверок не добавлялись.

**Установка PASS:** записано только application по `0x10000`; выполнены write verification и отдельный verify. До перезапуска контрольные суммы всего префикса flash `0x000000–0x010000` и области `0x480000–0x1000000` совпали со свежим резервным дампом. Загрузчик, partition table, NVS, файловые данные и coredump не изменились при записи.

После hard reset получены четыре чистых 5-секундных окна Home: 62.33–62.36 отрисованных кадров/с, render 5.534–5.554 ms, transfer 5.221–5.289 ms, battery 100, charging 0, panic 0. Это cadence renderer, не измерение частоты физического LCD и не доказательство всех сценариев сна.

Прежний резервный дамп проверен; перед установкой прочитан свежий полный дамп 16 MB. Установленное прежнее приложение побайтно совпало с сохранённой проверенной сборкой. Текущая таблица считана с устройства и совпала с проектом: application `0x10000`, ёмкость `0x470000`, данные с `0x480000`.

Дампы и данные устройства хранятся отдельно и не входят в исходный архив. Никаких erase_flash, factory reset, записи partition table, форматирования LittleFS/SD или push не выполняется.

## Производительность

На одной LilyGO снято по 24 прогона / 768 timed frames для прежнего и нового образа. Радиообработчики не вызывались. Первая after-попытка ожидала выключенный idle-экран и исключена; повтор после обычной перезагрузки завершился полностью, panic 0.

| Fixture | Прежний cached pipeline, ms | SAKURA cached, ms | Изменение | SAKURA worst p95 / p99, ms | Байт/кадр, old → new |
|---|---:|---:|---:|---:|---:|
| Settings | 18.139 | 13.290 | −26.7% | 13.323 / 13.408 | 38400 → 21760 |
| Wi-Fi main | 18.707 | 13.242 | −29.2% | 13.274 / 13.351 | 42240 → 21760 |
| Wi-Fi results | 21.645 | 21.407 | −1.1% | 21.433 / 21.492 | 53760 → 53760 |
| BLE config | 17.522 | 17.021 | −2.9% | 17.032 / 17.120 | 24320 → 24320 |

В новом образе full → cached: Settings 22.552 → 13.290 ms; Wi-Fi main 22.494 → 13.242 ms; results 26.100 → 21.407 ms; BLE 26.110 → 17.021 ms. Full push — 108800 B; для Settings/Wi-Fi main cached payload меньше на 80%.

Чистый Home прежнего образа: 62.48 renderer FPS за одно окно 5.010 s; SAKURA: 62.33–62.36 за четыре окна. Улучшение Home FPS не заявляется. Значения 5.19/5.30 FPS сразу после blocking benchmark исключены.

В SAKURA benchmark heap free 145435 B до и после, minimum-ever heap 145203 B к завершению; free PSRAM 8043660 B. Отдельный snapshot: heap free 145019 B, total heap 267651 B. Прежний snapshot: 143883 / 267659 B; PSRAM тот же. Это разные моменты времени, не доказательство улучшения памяти или отсутствия утечек. Три framebuffer занимают 326400 B.

Host-изоляция: cached Home median около 5.6 µs, p95 6.3 µs, p99 7.4 µs; 7/14/22 лепестка около 0.6/1.2/1.8 µs. Эти CPU timings зависят от Windows и нагрузки сборки, не являются значениями ESP32. Физические затраты фона/лепестков по отдельности и total allocation count не измерены.

В минутной смешанной пользовательской проверке получены три INPUT batch: n=32, median 14.155 ms, p95 23.142 ms, max 298.551 ms; n=13, median 12.873 ms, p95/max 1996.231 ms; n=8, median 22.229 ms, p95/max 34.302 ms. Это sample-timestamp → completed-present без per-event scene/wake attribution. Хвост около 2 s не скрыт; его нельзя выдавать за устойчивую задержку энкодера или отбрасывать без причины. Оценка пользователем нормального отклика зафиксирована отдельно.

Независимый host-аудит реальных функций воспроизвёл одинаковое время как при восстановлении старого canvas после off, так и при действительно отложенном present. Удержание Back с отменой countdown также блокирует main loop до отпускания. Поэтому этот смешанный журнал не устанавливает причину выброса и не доказывает 2-секундную задержку обычной навигации; per-screen input-to-visible-frame bound не заявляется.

Host-база и after используют замороженные ревизии shared renderer. Кэш статичного фона и повторно используемые PSRAM buffers сохранены. После превышения бюджета кадра на 2 ms Home на секунду снижает декоративные лепестки до Low и выключает glitch, не меняя сохранённую настройку. При выключенных лепестках они не включаются.

Host measurements не являются FPS LilyGO. Device benchmark сравнивает полный и cached путь одной и той же fixture внутри образа; old/new оформление различается. p95/p99 — worst percentile отдельных прогонов, не pooled. Для 32 samples nearest-rank p99 совпадает с максимумом. Global allocation count остаётся **не измерен**; нулевой C++ `new` внутри host paint не означает нулевые аллокации всей firmware.

## Что остаётся проверить

Пользователь подтвердил вид и отклик Home / Wi-Fi / BLE, стабильность батарейки и нормальный сон/пробуждение. Фото и колориметрические измерения не получены. Полный цикл после зарядки, ток настоящего Deep Sleep, камера телефона, длительная стабильность и весь набор аппаратных инструментов требуют отдельной квалификации. Смешанная INPUT-телеметрия не заменяет отдельный тест задержек переходов. Публичный адрес кошелька не задан; seed/private key не создавались.
