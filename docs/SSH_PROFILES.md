# SSH Profiles

Путь: **Wi-Fi → SSH Profiles**. Создайте профиль и введите свои name, host, port и user. Начальный список пуст; примеры с вымышленными адресами не создаются. Поддерживается до 12 профилей, порт 1–65535. Текущий transport использует IPv4 DNS; IPv6 ещё не квалифицирован.

Карточка профиля позволяет изменить, удалить, закрепить его или выбрать **Connect**. Открытие из Favorites показывает карточку; соединение и команды автоматически не запускаются. Переименование сохраняет ID, удаление убирает ссылку из Favorites. В Recent записывается только общий экран SSH Profiles.

Пароль запрашивается для подключения, живёт в RAM и очищается при выходе. В NVS `sakura_ssh` сохраняются только ID, name, host, port и user. Избранное хранится отдельно в `sakura_quick`. Пароль не попадает в настройки, Git или экспорт. Существующий терминальный журнал может содержать вывод сервера; не публикуйте личные журналы.

Известный ключ проверяется до аутентификации. При первом соединении устройство показывает SHA-256 fingerprint: сверьте его с сервером и подтвердите доверие явно. Изменившийся ключ отклоняется. Если `/littlefs/known_hosts` нельзя сохранить, вход отменяется; проверка ключа не отключается.

Back запрашивает завершение worker и оставляет экран ожидания до освобождения ресурсов. DNS ограничен 5 секундами; TCP/SSH handshake, аутентификация и открытие shell — отдельными 15-секундными пределами; ожидание решения о ключе — 60 секундами. Отмена проверяется между неблокирующими шагами. Ошибка не объявляется успешным подключением. Автоматических команд и SSH Macros в этом пакете нет.

Host-проверки выполняют фактические валидаторы, storage, trust policy и неблокирующие шаги с заглушками; это не проверка реального SSH-сервера. Независимое ревью исправило потерю частей команды при partial write/SSH_AGAIN и обычную очистку внешнего socket. В установленной libssh остаётся отдельно отмеченная особенность аварийного закрытия дескриптора; см. [известные проблемы](KNOWN_ISSUES.md).
