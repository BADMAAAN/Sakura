# FLUX DELTA — Cyber Sakura: UI и производительность

Базовая версия: `4003f2cb4f511b5e8d600c9d75e50c766518e04e`, установленная и проверенная ранее на той же LilyGO. Новая ветка: `codex/delta-cyber-smooth`, отдельный проект `C:\Projects\FLUX-DELTA`. Старый `C:\Projects\FLUX` остаётся без изменений.

## Визуал

Использован предоставленный PNG сакуры: дерево слева, луна и чёрное пространство справа. Исходное изображение сохранено в `assets/delta/cyber-reference.png`, SHA256 `85a88ba083a543d16801abf81c0b8ac2d2fc15e874dd045c351cbf0cadc6a73d`. Оно кодируется в прежний нативный indexed background 320×170/64 цвета; размер таблицы не вырос. Справа остаются один значок и название. Во внутренних экранах фон гораздо темнее и не конкурирует с текстом.

Основные режимы получили крупные нативные сглаженные заголовки 25 px, подписи 12 px и рабочие строки 14 px. Wi-Fi сохраняет отдельную область RSSI/channel/security; BLE — список режимов и четыре компактных поля с отдельным START; RF — частоту, реальный peak/RSSI, оси и измеренный график. Settings, Appearance, Files и Scripts используют ту же типографику и фон, сохраняя существующие действия. Новые приёмы применены в C++ прошивке.

[До/после и все новые экраны](FLUX-DELTA-CYBER-VISUAL.md): 90 нативных кадров в трёх темах, включая 12 основных экранов и пустые/неизмеренные состояния. Это **HOST FIXTURES**, не фотографии устройства. Синтетические сети и отсчёты существуют только в явно обозначенных проверочных сценариях; рабочие обработчики получают прежние реальные данные.

## Что меняет стоимость кадра

| Изменение | Практический эффект |
|---|---|
| Готовый фон в PSRAM | Полный indexed decode/blend больше не повторяется на каждом кадре; фон пересоздаётся при смене темы или Home/work |
| Shadow кадра LCD и изменённые полосы | Передаются только изменившиеся полные строки; неизменный кадр не вызывает SPI-запись |
| Ограниченное объединение полос | До двух неизменённых строк между полосами объединяются; при ≥75% высоты или >12 полосах используется полный кадр |
| Владение и сброс кэша | Новый экран, legacy drawing, частичная ручная запись, выключение/пробуждение панели и software sleep сбрасывают shadow; первый кадр полный |
| Приоритет входных событий | Декоративный кадр пропускается перед уже ожидающим вводом; интервал ожидания DELTA submenu сокращён с 10 до 1 ms |
| Select после открытия | У DELTA с энкодером убрана безусловная пауза 600 ms; удержанный входной Select блокируется до физического отпускания, новый принимается сразу |
| Выбранный пункт сразу виден | На Home нет прежнего ожидания затухания исходного пункта; новейший выбор виден с первого кадра перехода |
| Меньше overdraw | Убраны полноэкранный alpha fade при открытии и дополнительные полупрозрачные RF traces; остаются локальные акценты |

Кэш фона и LCD shadow занимают по 108800 B PSRAM, всего 217600 B. Выделяются один раз, без выделений на каждом кадре. Если память недоступна, остаётся обычный полный рендер/передача. Параметры протоколов и обработчики действий не заменялись. Контроллеру по-прежнему передаются RGB565 данные с прежним byte swap.

## Измерения

Хостовый baseline: 9 повторов по 500 отрисовок после 100 прогревочных вызовов, существующий Zig `-O3`. Медианы: Home 19.71 µs, Settings 34.41 µs, Wi-Fi main 144.25 µs, Wi-Fi results 161.50 µs, BLE config 149.63 µs. Это CPU компьютера, без LCD; они не считаются аппаратными FPS. Изолированная копия исходников базовой версии сохраняет воспроизводимость.

Диагностика `delta_bench` запускается только явной командой и обслуживается главным UI task. Она не вызывает модули, не сканирует и не передаёт радио. На экране появляются явно обозначенные BENCH FIXTURE. Для каждого из четырёх новых экранов выполняются прогрев и 3×32 одинаковых переключения: контроль с полной перерисовкой/передачей против кэша и diff. Это сравнение двух путей **одного нового интерфейса на одном устройстве**, а не измерение старой прошивки целиком. Измеряются render, present, медиана/p95/max времени кадра и фактическое число переданных байт. Энкодер или Select/Back прерывают диагностику.

Отдельный физический замер начинается при обнаружении движения энкодера в InputHandler и заканчивается после передачи первого кадра нового выбора. Он включает планирование UI и LCD transfer, но не время от механического контакта до опроса и не проверяет свечение пикселя фотодатчиком. Данные выводятся агрегатами без имён сетей или настроек.

Аппаратный тест: **24 серии, 768 измеренных кадров**, прогрев исключён, panic 0. Числа ниже — медиана трёх медиан по 32 кадра; p95 взят как максимум p95 трёх серий. Контроль и оптимизация рисуют одинаковые новые сцены на одной LilyGO.

| Сцена | Полный путь → оптимизированный, ms | Сокращение времени | p95 нового пути, ms | Байт/кадр нового пути |
|---|---:|---:|---:|---:|
| Settings | 32.430 → 18.141 | 44.1% | 18.165 | 38400 |
| Wi-Fi main | 32.572 → 18.701 | 42.6% | 18.706 | 42240 |
| Wi-Fi results | 33.554 → 21.631 | 35.5% | 21.657 | 53760 |
| BLE config | 33.816 → 17.522 | 48.2% | 17.540 | 24320 |

Контроль всегда передавал 108800 B/кадр; сокращение составило 50.6–77.6%. Числа steady-state совпали с независимой моделью dirty bands. Это время работы pipeline без лимитера и yield, а не обещание такого FPS во всех работающих инструментах.

Ранее установленная версия показывала Home 47.3716 FPS за 45 s, render 6.489 ms, LCD 13.771 ms. После отдельного чистого перезапуска **без записи flash** новый Home измерен 45 s, восемь полных окон по 5 s: около 62.44 кадров/с, render 5.534 ms, present 5.254 ms, panic 0. Встроенный счётчик считает отрисованные кадры; LCD получает только изменённые полосы. Это cadence движка с 16-ms лимитером, не измерение физической частоты обновления LCD. Первое загрязнённое диагностикой окна 8.44/8.71 FPS исключено; их время включало BENCH.

Рабочие экраны старой версии отдельно не измерялись. Аппаратный стенд демонстрирует выигрыш нового пути при одинаковой графике; не следует выдавать его за замер старой прошивки целиком.

Первый вариант измерителя ошибочно связывал старую отметку энкодера с новым экраном: зарегистрирован максимум 1350816 µs. Этот опыт сохранён и **полностью исключён** из численной оценки отклика. Причина воспроизведена независимо; запись теперь начинается только при фактическом nonzero drain, а Home hover сохраняет событие до presentation. Регрессия проверяет отсутствие ложной записи при построении страницы, один результат для одного события и отмену при смене владельца. В повторном журнале достоверных физических samples не получено, поэтому медиана/p95 задержки энкодера **не заявляются**. Пользователь повторно подтвердил нормальное управление; это субъективная проверка, отдельно от аппаратного pipeline benchmark.

## Проверки и границы

65 тестов после последних изменений: PASS, 19.279 s. Включены реальные runtime entry points, точная реконструкция LCD из dirty bands, cold/unchanged/one-row/legacy/partial/invalidate, fallback, темы, кадровые границы, BLE control parity, моментальная видимость выбранной Home категории и actual Select release gate. Независимые code/visual review: PASS. Контраст основных palette tokens не ниже 4.82:1; это не измерение физической панели.

Финальная сборка PASS, 156.36 s; независимый artifact audit PASS. Application 4393744 B (на 4496 B меньше предыдущей), SHA256 `27ea2c39fd2b1050c98b73cd1f34dbeaf87e02a4dff9d4fd779a3037b15ab125`. Static RAM 133152 B (+184), запас factory 259312 B. Код: `e3a52b35`. Устройство ESP32-S3 rev0.2 / MAC 90:70:69:0a:e2:f0 / 16 MB. Приватный резервный дамп проверен по прежнему SHA256; таблица live == backup == build. Запись только application `0x10000` за 34.2 s, verify application + прежних bootloader/table PASS, штатный hard-reset и новая телеметрия подтвердили запуск. Пользователь подтвердил плавный отклик, работу Back, отсутствие следов кадров, читаемые крупные заголовки и цельный фон; управление на финальной версии проверено повторно.

NVS/LittleFS/SD не стирались, LittleFS autoformat остаётся выключенным, полный приватный дамп повторно не снимался и в архивы не включается. Загрузка не равна проверке радиопротоколов.

Компромиссы: три более крупных строки вместо пяти в основных режимах; RF plot 48 px высотой ради крупного заголовка и чисел; фон внутренних экранов почти чёрный; меньше эффектов и сплошных подложек; дополнительная PSRAM ради меньшей работы CPU/SPI. Максимальные 60 FPS не являются обещанием. Полное Unicode покрытие, live RF/Wi-Fi acquisition, ток и Deep Sleep/wake в эту аппаратную проверку не входят.

После ручной навигации один read-only снимок: heap total/free 267659/144975 B; PSRAM total/free 8388608/8043660 B. Это не длительный тест утечек.

## Локальная поставка

Исходники, графика, preview/tests/docs, 38 публичных библиотек, проверенная application, metadata и `source-history.bundle` сохранены в `artifacts/FLUX-DELTA-CYBER-SOURCES.zip`. Для воспроизведения исторических сравнений после распаковки в отдельную новую папку: `git init`, `git fetch source-history.bundle HEAD`, `git reset --mixed FETCH_HEAD`. Точные распакованные файлы сохраняются. Компиляторы и Python окружение остаются установленными локально и не входят в исходный архив. SHA256 ZIP записывается рядом без самоссылки. Push/release не выполняются.
