# SAKURA 0.3.1-back: Wi-Fi и владение BLE

Продолжение [пакета 0.3.0](FEATURE_PACKAGE.md). Одобренные сцена, шрифты, Home, палитра, батарея, sleep/wake и защита LittleFS не менялись. Это ограниченная доработка выхода; полный P0 всего дерева Bluetooth остаётся открытым.

## Wi-Fi

Прежний фактический `_connectToWifiNetwork` на инертном backend ожидал 10 510 мс, оставляя Back непотреблённым. Общие foreground-пути подключения и сканирования теперь опрашивают отмену с шагом 20 мс. Отдельный результат Cancelled/Busy передаётся через Retry, известные сети, startup WebUI и serial AP fallback; отмена не запускает следующую сеть, AP, сервер, сохранение credentials или timezone task.

Один короткий guard отделяет foreground от фонового auto-connect; фоновый код не читает Back и освобождает guard до удаления собственной задачи. Существующие AP, подключённая STA, scan и активный WebUI не перехватываются. При отмене своей попытки запрашивается disconnect без стирания настроек, затем проверяется отключение только STA и отсутствие её mode bit; AP сохраняется. Успешный disconnect сам по себе не считается подтверждением остановки: у не подключившейся станции может не быть нового ASSOC_LEAVE. Эта ошибка была воспроизведена независимым тестом и исправлена.

Async scan использует штатный stop и ждёт SDK SCAN_DONE до освобождения результатов. Таймаут wrapper не подменяет остановку драйвера. Ошибка stop сохраняет экран ожидания завершения. Контракт async scan stop описан в [ESP-IDF 5.5.4](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-guides/wifi.html#wifi-event-scan-done); конкретная реализация сверена с установленными исходниками Arduino/IDF.

## BLE Suite

Регистрация клиента стала идемпотентной; unregister удаляет все старые дубликаты. Обычное освобождение Suite-клиента проходит disconnect → NONE → подтверждение очереди NimBLE host → unregister → delete. Для cleanup не создаётся отдельная задача. Отказ сохраняет клиент и правдивое состояние; отмена запрещает следующий delay/init/attempt.

Обычный Suite cleanup сохраняет общий BLE host. Вход отказывает при чужом scan, advertising, server/HID или созданном клиенте, включая ещё не подключённого. Выход, возврат после действия и свежий вход не обходят оставшиеся owned clients: ошибка сохраняется на экране, новый Back повторяет cleanup. Вложенное меню не сбрасывает отмену и не удаляет клиент, которым ещё владеет его родитель.

Унаследованный `executeRapidConnection` сбрасывал владельца перед записью через прежний characteristic pointer. Этот неисправный путь теперь явно отвечает unavailable до радиоопераций; его прежнее поведение не выдаётся за сохранённую работающую функцию.

## Проверки и границы

Новые тесты используют фактические production bodies и инертные SDK/UI. Они покрывают отсутствие disconnect event, неудачную остановку, чужой AP/WebUI/клиент, late callback, освобождение после ошибки, свежие нажатия, запрет следующего действия и старые поведенческие мутации. Это не замер задержки или числа задач на LilyGO.

Физический Back ранее подтверждён пользователем для hotfix 0.2.1 BLE Spam config без Start и для 0.3.0 Recent screens / SSH Profiles / QRCodes. У 0.3.1 проверена загрузка; отдельного пользовательского физического Back PASS этой версии нет. Сетевой SSH-сервер, QR камерой, worst-case stack-watermark и длительный радио-регресс не квалифицированы.

Открыты синхронные lazy discovery/refresh/read/write/security и часть цепочек BLE/HFP, model callbacks Ninebot с задержками и отдельное владение HID-server. Инертные проверки новых общих helpers не закрывают эти пути. Подробности — [известные проблемы](KNOWN_ISSUES.md).

## Воспроизводимость

Проверка сохранённого ZIP 0.3.0 в отдельной папке дала успешную обычную сборку, но resolver скачал обновлённые четыре исходника WireGuard. Поэтому её новый hash не является точным воспроизведением установленного образа. Проба убрать `lib_deps` оказалась неверной: PlatformIO удаляет сохранённые зависимости; она отмечена FAIL, а не скрыта.

В 0.3.1 WireGuard закреплён на уже использованном commit `4e22d2e16b70072c105de577d4e79350c1eec932`. Версия библиотеки и BLE-стек ради исправления не меняются. Полный локальный ZIP с сохранёнными зависимостями отличается от фильтрованного состава для GitHub; в публичный репозиторий большой архив и приватные rollback-дампы не входят.
